About MeshCrowd

A chat platform for people who would rather own their conversations than rent them.

Why it exists

Communities deserve a home that does not change its rules, its prices or its privacy policy overnight. MeshCrowd gives a group of any size the tools people are used to from big chat services, running on a machine the group controls: a spare PC, a small server or a rented VPS.

It is deliberately boring to operate. There is one Node.js process, one SQLite database file and a folder of uploads. A backup is a copy of one directory. There are no accounts with a third party, no analytics, and the web client loads nothing from outside your server.

Transparent

Plain HTML, CSS and JavaScript modules with no build step. You can read exactly what your browser runs.

Private by default

Encryption where it matters, honest notes about where it cannot help, and no telemetry at all.

Free for everyone

No paid tiers or boosts. Every server gets every feature, under the GNU General Public License.

What it is made of

LayerTechnology
ServerNode.js 22.5+, Express, ws for WebSockets, the built-in node:sqlite database
Web clientPlain ES modules, no framework and no build step; DOMPurify, highlight.js, CodeMirror and TinyMCE are bundled locally
Voice and videoWebRTC mesh, Opus, optional RNNoise compiled to WebAssembly, built-in STUN/TURN relay (plain Node, no dependency)
DesktopElectron, as a portable Windows app
AndroidKotlin WebView shell with WorkManager and optional UnifiedPush

Built together with Claude

AI involvement

MeshCrowd was designed, written and tested in close collaboration with Claude, an AI model made by Anthropic, working as a coding assistant under the direction of the project owner. Claude wrote and reviewed large parts of the code, the tests and the documentation, drove real browsers, the desktop client and an Android emulator to check the result, and also built this website.

The owner decided what to build, what to leave out and when a result was good enough. Every feature was exercised against a running server before it was called done, and the project keeps a large automated test suite. Treat it like any other software: read the code, run the tests and report what you find.
