Messaging

Everything you expect from a modern chat, with the rough edges smoothed out.

  • Edit, delete, reply, forward and react with Unicode and custom emoji, plus stickers.
  • Threads off any message and forum channels made entirely of threaded posts, with a Threads panel per channel. Forum posts show as cards with previews, thumbnails, search and sorting.
  • A red "New" line marks the first unread message when you open a chat, and the view jumps there. How far it jumps and how many messages load is up to you.
  • Polls, pins, link previews, code blocks with syntax highlighting and spoilers.
  • Voice messages up to five minutes with an inline player, recorded in the browser, desktop app or phone.
  • Scheduled messages: pick a time and the message is posted as you, with the same checks as a normal one.
  • Search across message text (SQLite FTS5), usernames, channel names and attachment names.
  • Up to five attachments per message, optional image resizing before upload and a play/pause button on GIFs.
  • Autocomplete for @mentions, #channels, emoji shortcodes and slash commands.

Voice and video

Calls run peer to peer over WebRTC: there is no media server to install, host or pay for.

  • Voice channels, stage channels and private DM calls with camera and screen share as separate tiles.
  • Quality presets chosen when a channel is created: Mobile, Low, Medium, High and HD Music, from 8 kHz up to 48 kHz stereo.
  • Optional RNNoise noise suppression, a small neural network that runs on your device.
  • Per-person volume, speaking rings, a live level strip, input device picker and a server soundboard.
  • Stage channels with speakers and audience, raise hand and invite to speak.
  • Mute for everyone for moderators, and fullscreen for any video tile.
  • A resizable call panel: large, scrollable tiles above the text chat, with a divider you drag to give the room or the chat more space.
  • Built-in STUN and TURN so calls connect across routers and NAT with no third-party service. Off by default, set up with one script or from the Admin Panel.
Good to know

A full mesh means every participant sends to every other participant, so calls of roughly eight or more people with video need good upload bandwidth. On one network calls just work. For people on different networks turn on the built-in STUN and TURN server (setup-turn.bat or the Admin Panel, Calls) and forward UDP and TCP 3478 plus UDP 49152-49999 on your router. Only the call audio and video ever use it; chat and signaling always go through your server. How to set it up.

Servers, channels and roles

Nothing is hard-coded: roles are bit flags you edit, and every channel can override them.

  • Categories with drag-and-drop ordering of channels and categories.
  • Roles with 17 permissions, colors and icons (an emoji or an image). Nobody can grant a permission they do not hold.
  • Per-role and per-user channel overrides, slowmode, topics, icons and a welcome screen.
  • Private Notes channels: an encrypted notebook for every member, unreadable even by admins.
  • A personal server rail with folders, and a discoverable directory of public servers.

Community tools

Grow and look after a community without any extra services.

  • Invites that expire and have use limits, plus a vanity link people can type instead of a code.
  • Invite links: /i/<code> opens a join page with Join in browser and Open in app (mcr:// links open the desktop and Android apps, always asking before joining).
  • Onboarding: new members read the rules, answer up to five questions that hand out roles, and accept before they can post.
  • Reaction roles: react with an emoji to get a role, optionally exclusive.
  • Server templates that copy structure and permissions, never people, messages or invites.
  • Insights with growth and activity charts for 7 to 90 days.
  • Scheduled events with RSVP, and a welcome screen with highlighted channels.

Moderation and safety

Practical tools that act before a problem spreads, and leave a record of what happened.

  • AutoMod: blocked words, links (block, allow or deny lists), mass mentions, spam and too many capitals, with optional timeouts and exemptions.
  • Verification levels hold back brand-new accounts and recent joiners. Everything is local; no email or phone check.
  • Age-restricted channels behind a one-time click-through. Nothing is verified and nothing leaves your server.
  • Kick, ban, timeout, audit log and a user reports queue.
  • Data pruning to delete history older than a date, with a preview and an optional 24-hour notice.

Bots and automation

One bot account can be an AI chat partner, a scripted integration, or both.

  • AI bots backed by Ollama or any OpenAI-compatible service. They answer mentions and, if you allow it, private DMs.
  • Bot API with tokens, and HMAC-signed outgoing webhooks that work with n8n, scripts and CI.
  • Slash commands published by a bot, with typed options, a popup in the composer and chips on the phone.
  • Ephemeral answers that only the person who ran the command can see and that are never stored.
  • Incoming webhooks per channel for scripts that only need to post.
Privacy note

Everything an AI bot is asked is sent to its provider. Bots never read end-to-end encrypted DMs, group DMs or Notes channels, and only see channels their role can view.

Sites

A Site is a server kind that serves a folder of PHP, HTML, CSS and JS pages inside the app: a team wiki, a rota, a small tool.

  • Appears in the server rail and renders in a same-origin frame, with no channels or notifications.
  • Built-in code editor (CodeMirror) and a visual editor (TinyMCE) that keeps PHP blocks intact.
  • A portable PHP runtime is bundled for Windows; elsewhere use your own PHP.
Trust

Site pages run as part of MeshCrowd. Only give edit rights to people you would give server access.

Federation

Two servers can be paired so that people on one can reach people on the other. It is off by default and never happens by accident.

  • Pair with an invite link; each side explicitly accepts or rejects the other, and revoking drops trust on both sides.
  • Share friend requests and DMs, list each other's public servers and join with a code@domain invite.
  • Remote servers are proxied live, never copied. Permissions are always decided by the server that owns the community.

Identity and privacy

Strong defaults, and honest documentation about what the limits are.

  • Passport: an account key pair created in your browser, exportable as an encrypted .mcpass file for sign-in and recovery.
  • Strengthened sign-in: the browser derives the sign-in key; the server never sees the password of a web account.
  • End-to-end encrypted DMs with safety numbers and key pinning.
  • Two-factor authentication with TOTP and recovery codes, revocable server-side sessions and rate limiting.
  • HTTPS by default with an automatic certificate, or bring your own.

Read the security model for details and known limits.

Personalization

The interface adapts to people, not the other way round.

  • Themes per user: presets or your own colors, fonts and a background gradient, shareable as a snippet.
  • Profiles with avatar, banner, bio, custom status and presence, plus per-status sound rules.
  • Resizable sidebars, name colors, server folders and a language switch (English and Hungarian).

Clients

Use whatever suits the moment. They all talk to the same server.

Web

Nothing to install, every feature available in any modern browser.

Desktop

A tray badge with your own colors, native notifications, close to tray and certificate pinning for self-signed servers.

Android

A phone-first interface with local background notifications and optional UnifiedPush, no Google services needed.

Administration

Run it like a service, even when it lives on a small box.

  • Admin panel with stats, user management, staff ranks and instance-wide server management.
  • Runtime upload size limit and optional extension allowlist.
  • Portable bundle with its own runtime, and a backup that is just a folder copy.
  • Plenty of automated tests (the suite currently has more than 700).
